## 本次统一的口径

本机成员盘点与 Git 实验归档回答的问题不同：前者盘点手头资料和数据线索，后者保存已有运行的聚合结果。网站现在把两者放在同一证据体系内，但不覆盖原文、不将不同来源的样本数相加，也不把“查到公开数据”改写成“已经获得并验收”。

9 月 13 日会议继续提出历史结果交接、数据标签整理、网站部署和医院反馈事项。会议没有为这些事项确定完整日期；日历将它们列在“待定安排与未约定 DDL”，不把建议人日、“国庆后”或外联设想推算成承诺。来源见 [会议总结](meetings/2026-09-13/2026.9.13会议总结.txt) 与 [会议原文](meetings/2026-09-13/2026.9.13会议原文.txt)。

## 网站使用与维护

- `#calendar`：月历、月度清单、事件类型及内容搜索。点日期查看会议/工作记录，点报告名打开对应证据；方向键可移动日期。
- `#evidence`：来源文件树。按研究报告、成员调研、处理记录及历史训练分类，支持目录/文件搜索和下载。
- `#evidence?section=meetings`：与来源文件同级的会议记录菜单，按日期展示报告和原文，并链接到日历。
- `#evidence?source=<来源ID>`：可分享的报告定位链接。PDF 打开原件，文本在弹窗预览；大型指标文件只预览前 200,000 字节，下载保留完整文件。

工作日志与具有明确单日日期的研究历程自动进入日历，关联原记录或已有报告；跨日/语义不明确的历程仍在原历程页，不任意归入一天。会议及人工维护日程保存到 `progress-dashboard/calendar.json`。新增/编辑包含类型、日期、可选钟点、说明和关联报告；无日期允许保存为待定。并发修改会提示刷新，不静默覆盖。历史日志在原文件维护。

网页保存只修改本机文件，不自动推送 Git。团队共享由维护者提交 `calendar.json`；这避免每次个人编辑直接改动远端主分支。Git 更新并不等于公网部署，本地网站仍只监听回环地址。

新增材料时，把可发布的文件放入仓库，在 `progress-dashboard/imports.json` 中登记路径、日期及来源；执行 `python scripts/build_dashboard_archive.py` 重建白名单后，提交原件、清单和 `archive.json`。生成器同时读取组长的 CSV 报告目录及归档 inventory；不递归开放任意磁盘文件。导入原件的 SHA-256 保存在索引中。本次原件复制后逐一与本机源文件核对一致。

原始影像、逐人临床数据/预测、模型权重、密码令牌、原音频和本机 QC 审核数据库不在本次新增上传范围。原文中的旧本地相对链接可能未随原件迁移；可由本说明和来源树找到已归档同名材料，未归档材料不生成假链接。

验证命令：

```powershell
python scripts/build_dashboard_archive.py
python -m unittest discover -s progress-dashboard/tests -v
node progress-dashboard/tests/test_calendar_ui.cjs
node --check progress-dashboard/public/archive-ui.js
```
