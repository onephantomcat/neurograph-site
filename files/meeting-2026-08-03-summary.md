# 2026.8.3 会议内容详细总结

## 一、会议主题

本次会议围绕“基于 fMRI/脑信号的疼痛识别与分级项目”当前进展、数据来源、模型路线、医院合作采集数据以及后续分工展开。会议重点不是重新讨论项目是否继续，而是明确：项目需要继续推进，并且要加快节奏，尤其要把模型路线和跨疾病适配思路尽快理清。

## 二、核心结论

1. 项目不会暂停，仍然要继续向前推进。
2. 医院方面已有其他科室或外部团队在做类似的脑信号识别工作，说明该方向具有现实需求和竞争压力，团队需要加快动作。
3. 当前项目不能只依赖医院新采数据，必须同步推进公开数据集上的模型研究，形成保底方案。
4. 后续研究重点应从“数据预处理和数据规范化”逐步转向“模型本身”，尤其是跨疾病 fMRI 分类、预训练模型迁移、脑图谱适配和小样本条件下的自适应训练。
5. 医院临床数据仍然非常重要，即使短期内拿不到完整数据，也必须让医院参与讨论，以确认项目未来临床价值和真实使用场景。

## 三、当前项目背景与外部情况

会议开始时提到，老师近期与医院医生沟通，了解到已有其他科室正在与外部团队合作，也在做类似的“用脑信号识别疾病或状态”的工作。该方向与团队当前“用 fMRI 做疼痛识别/分级”的思路接近。

这带来两个判断：

1. 该方向不是孤立设想，已经有不少团队在关注，说明研究方向有价值。
2. 团队原本认为该方向尚不成熟、大家还在探索，但实际上外部推进速度可能比预期更快，因此当前项目需要提高执行效率。

老师强调，不要求结题内容与申报书百分之百完全一致，但大方向指标要对齐，比如论文、专利、项目成果等。实际执行中，如果某些原计划模型效果不好，可以调整路线。

## 四、已有数据与预处理进展

### 1. 公开数据集使用情况

团队此前在申报大创项目时使用过一个公开数据集，并完成了一些初步工作。该数据集存在较明显的质量问题，尤其是在预处理后发现部分被试数据不合格。

不合格数据的判断依据主要包括：

1. 预处理完成后生成的脑图中存在大面积空白，说明部分脑区没有有效扫描到。
2. FC 矩阵中存在大面积为 0 的区域，这类数据不能正常用于后续模型训练。
3. 部分数据存在没有对齐的问题，需要通过额外对齐步骤或修复流程处理。

### 2. 数据修复情况

此前有一部分被试因为预处理不合格被筛掉，后续团队发现部分数据可以通过增加对齐步骤、调整预处理流程等方式修复。

会议中提到，原本 76 个被试中只剩 54 个，结果可能偏乐观；后续通过修复流程，部分被试数据被成功恢复。修复后主要获得了：

1. FC 矩阵。
2. ROI 脑区时序图。
3. 基于 AAL90 脑图谱的结果。

其中，AAL 模板从原先包含小脑区域的默认模板调整为 AAL90，因为当前任务不使用小脑区域。

### 3. 服务器与 agent 辅助处理

团队已接入实验室服务器，能够通过远程命令行调用服务器资源进行预处理。服务器为 Linux 系统，运行速度预计比 Windows 更快。

目前 agent 的主要用途是辅助跑数据预处理。后续老师建议，agent 不应只用于处理数据，也可以进一步用于调用不同模型库、管理模型池、比较不同模型结构下的性能，并持续辅助优化。

## 五、新数据集与公开数据方向

团队正在寻找和整理新的、更大规模的公开数据集。会议中提到一个数据集包含：

1. 115 名患者。
2. 52 名健康对照。
3. 共 167 名被试。
4. 总计约 229 次影像扫描，说明部分被试可能有多次扫描。

会议认为，如果新数据集质量较高，可以减少后续质控和修复成本，并提升模型训练精度。

目前科研侧的保底路线是：先使用公开数据集，把模型和方法跑通，尤其探索跨疾病场景下的 fMRI 分类与模型适配。即使医院数据暂时不能及时提供，团队也应先基于公开数据形成可展示、可发表、可继续扩展的成果。

## 六、模型路线讨论

### 1. 当前已有 baseline

团队目前已有基于 SVM 的 baseline，也尝试过引入脑图谱/脑网络相关模型。会议中提到，使用脑图谱后精度有提升。

当前脑图谱主要被用于特征节点构建，然后输入模型进行训练。

### 2. 当前模型问题

老师指出，目前团队面临两个核心问题：

1. 数据量不够，尤其是被试数量较少。
2. 疼痛相关 fMRI 分类文献较少，可直接参考的成熟模型不多。

因此，直接训练大型复杂模型并不现实。更合理的方向是在小样本条件下，探索如何自适应地训练出较好的模型，或利用已有预训练模型辅助。

### 3. 重点方向：跨疾病与模型适配

老师强调，当前脑疾病相关任务的主流趋势包括：

1. 跨被试者。
2. 跨疾病。
3. 跨域。

本项目很适合切入“跨疾病”方向。例如，将已有心理或神经相关疾病上的预训练模型迁移到疼痛识别任务中，并研究其如何适配新的疾病场景。

老师指出，直接复用已有脑图谱或已有模型可能能取得一定性能，但更有价值的问题是：模型如何针对新的疼痛疾病数据进行优化、微调或自适应调整。

后续应重点调研：

1. 跨疾病 fMRI 分类文章。
2. 不同疾病之间脑区连接模式迁移的方法。
3. 预训练脑网络模型如何适配新疾病。
4. 脑图谱是否直接复用，还是根据新疾病重新构建、调整或微调。
5. 小样本情况下如何进行自适应训练。

老师建议团队从文献中总结共性方法，再迁移到当前疼痛识别任务中。

## 七、医院合作与临床数据采集

### 1. 医院数据仍需继续推进

尽管已有其他科室在做类似工作，会议认为本项目不应停止医院数据采集。老师会继续与医院医生沟通，落实采集方案。

会议明确，医院侧数据采集与公开数据模型研究要双线推进：

1. 团队内部先用公开数据集推进科研模型。
2. 老师继续推动医院临床数据，争取后续真实场景数据。

### 2. 数据采集类型

当前计划采集的是静息态 fMRI 数据，即让被试者在不执行特定任务、不活动的状态下进行扫描。

### 3. 数据采集标准

团队此前已经向医院方面发过报告和具体操作建议。会议中再次强调，数据采集最重要的是“统一”：

1. 尽量让所有被试在同一环境下采集。
2. 扫描机器品牌和设备条件应尽量统一。
3. 脑扫描切片层数应统一。
4. 扫描顺序应统一。
5. 采集格式要符合团队后续预处理和模型输入要求。

原因是现有预处理软件通常会把所有被试统一放进流程处理，不一定能很好地区分不同设备或不同扫描条件下的数据。如果采集条件不统一，后续可能还需要额外修复和对齐。

### 4. 医院数据的困难

会议也讨论了临床数据采集的现实问题：

1. 医院确实有较多神经病理性疼痛患者，但不确定有多少患者愿意或能够做 fMRI。
2. 健康对照需要额外招募。
3. 健康对照进入 fMRI 扫描可能需要补贴。
4. fMRI 机器使用、扫描损耗等会产生费用。
5. 当前项目经费可能不足以完全支撑大规模临床采集。
6. 医院侧可能需要申请更大级别项目来支持数据采集。

老师表示会进一步与医院沟通数据、经费、采集计划和项目配套问题。

## 八、临床价值讨论

老师特别强调，疼痛识别具有很强临床价值。疼痛本身难以量化、难以客观干预，同时又会影响全身疾病和临床治疗。因此，用神经信号辅助疼痛评估是有必要的。

团队在答辩或项目阐述时，需要更清楚地说明：

1. 为什么疼痛任务值得做。
2. 为什么神经信号适合用于疼痛识别。
3. 为什么该方法对临床有价值。
4. 医院参与不仅是为了提供数据，也能帮助团队判断该技术是否真正适合临床使用。

即使医院短期内不能提供理想数据，也必须参与方案讨论，因为团队需要知道研究方向未来是否具有临床落地意义。

## 九、人员分工与当前协作情况

会议中提到团队成员分工大致如下：

1. 有成员主要负责 agent 调用、网络环境配置、实验室路由器和服务器接入等技术环境工作。
2. 子墨、吴明浩等成员负责查看预处理后的数据能做什么、整理结果、查找相关文献等。
3. 发言同学目前主要承担对接角色，对成员产出的预处理数据进行质控，并同步已有结果和相关知识。
4. 老师负责继续推动医院侧沟通，包括临床数据采集、经费、合作边界和项目价值讨论。

老师提醒，网络环境、agent、数据预处理等工作完成一轮后，要尽快切换到核心任务，即模型理解、模型复现、模型改进和跨疾病方法探索。

## 十、后续任务安排

### 1. 团队成员任务

1. 分工查找跨疾病 fMRI 分类相关文献。
2. 重点阅读文献中的模型方法，而不仅是数据集介绍。
3. 总结跨疾病任务中模型如何实现自适应、迁移、微调或脑图谱调整。
4. 整理哪些模型可以纳入后续模型池。
5. 在公开数据集上继续推进 baseline 和脑图谱模型。
6. 对预处理后的数据继续质控，保证 FC 矩阵、ROI 时序等输入可用。
7. 继续维护服务器、agent 和数据处理流程，但不能让这些工作长期占据核心精力。

### 2. 老师任务

1. 继续联系医院医生，确认医院侧是否能配合采集数据。
2. 明确医院数据采集方案、样本规模、设备条件和采集标准。
3. 沟通 fMRI 扫描费用、健康对照招募、经费来源等问题。
4. 向医院强调项目临床价值，并确认未来落地场景。
5. 对医院反馈及时同步给团队。

### 3. 下一次会议建议重点

下次会议应尽量减少对数据集整理和预处理流程的重复介绍，把重点放在：

1. 跨疾病 fMRI 分类文献调研结果。
2. 可复用模型清单。
3. 脑图谱/脑网络模型如何适配疼痛任务。
4. 当前 baseline 的性能与改进空间。
5. 公开数据集上的模型实验计划。
6. 医院侧数据沟通进展。

## 十一、风险与待确认事项

1. 医院数据采集是否能落地仍不确定。
2. 可采集患者数量、健康对照数量、fMRI 扫描费用尚未明确。
3. 医院已有其他科室在做类似方向，可能带来竞争压力，也可能影响本项目创新点定位。
4. 当前公开数据集存在质量问题，需要持续质控。
5. 疼痛相关 fMRI 文献较少，跨疾病迁移可能需要从更广泛的脑疾病分类文献中寻找方法。
6. 目前团队对模型本身的理解和改进还不够，需要尽快从“能跑通”转向“讲得清楚、改得出来”。

## 十二、会议最终共识

本项目继续推进，采用“双线并行”的策略：

一方面，团队内部基于公开数据集推进模型研究，重点攻克跨疾病 fMRI 分类、脑图谱迁移、小样本自适应和模型池构建；另一方面，老师继续推动医院侧临床数据采集，争取获得真实疼痛患者与健康对照的静息态 fMRI 数据。

短期内，团队最重要的任务是把模型路线吃透，尤其要弄清楚跨疾病任务中模型如何适配新的疾病场景。医院数据很重要，但不能成为项目推进的唯一前提。即使暂时没有医院数据，也要先用公开数据集做出可验证、可解释、可继续扩展的模型成果。
